== Event Types and Message Contents

NOTE: Tracing uses address compression to reduce the number of bits used to mark executed addresses.  A non-compressed address is referred to as a Full Address, or *F-ADDR*. A Relative Address, or *R-ADDR* is a reduced-width address and as the name implies, is relative to and calculated from previous Full Addresses.

NOTE: One purpose of a Sync is to re-establish a Full Address of an executed instruction in the trace stream in order for the decoder to properly determine the location of the next executed instruction. In most cases it also requires tracing the current Privilege level, and in some cases, tracing the current Context ID for the decoder to determine the process or task that is executing.

Note: Context and Context ID are used interchangeably in this document.

Definition: *CauseID*: traced value identifying the cause of a Trace-on (Sync) or Trace-off event. The Trace Decoder uses it to label the cause of the message. This document assigns ID values; these can be different between E-Trace and N-Trace. 

RHTI signals referenced in this spec: +
* trcstate[] +
* trigger[] +
* cause[] +
* priv[] +
* context[] +
* iaddr[] +
* iretire[]

NOTE: For exceptions and interrupts (itype=1 and 2 respectively), Event Trace deems it important to capture the xepc return address value. This was implemented in a pre-existing Event Trace implementation. +
The method: `xepc = iaddr + iretire`, when itype=1 or 2 +
where `iretire`` is the "number of halfwords represented by instructions retired in this block". +
Note that there are exception cases where no instruction is retired, where iretire=0.
