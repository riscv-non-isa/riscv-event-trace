== Event Types and Message Contents

NOTE: Tracing uses address compression to reduce the number of bits used to mark executed addresses.  A non-compressed address is referred to as a Full Address, or *F-ADDR*. A Relative Address, or *R-ADDR* is a reduced-width address and as the name implies, is relative to and calculated from previous Full Addresses.

NOTE: One purpose of a Sync is to re-establish a Full Address of an executed instruction in the trace stream in order for the decoder to properly determine the location of the next executed instruction. In most cases it also requires tracing the current Privilege level, and in some cases, tracing the current Context ID for the decoder to determine the process or task that is executing.

Note: Context and Context ID are used interchangably in this document.

Definition: *CauseID*, value traced identifying the cause of a Trace-on (Sync) or Trace-off event. The Trace Decoder uses it to label the cause of the message. This document assigns ID values; these can be different between E-Trace and N-Trace. 

RHTI signals (defined in spec): +
* trcstate[] +
* trigger[] +
* cause[] +
* priv[] +
* context[] +
* iaddr[]

NOTE: For exceptions and interrupts, Event Trace deems it important to capture the xepc return address value. (This is implemented in a pre-existing Event Trace implementation).  This can be accommodated over the RHTI be assigning the unused value 7 of ITYPE for this purpose.  The xepc address is carried over the (existing) *iaddr[]* field of RHTI. This would occur on the cycle after the already-defined *itype=1* cycle which carries the "address of the instruction which incurred the exception", as specified in RHTI.

Read-only implementation bits will be defined in the *trTeEvtFeatures* (later in this document) and the Enable bits in the *trTeEvtControl2* register.
